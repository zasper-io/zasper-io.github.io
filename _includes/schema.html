{% comment %} Structured data, which is the one part of this site's metadata a reader never sees: the tags in meta.html say what a page *is* to a crawler that already has it, and this says how the pages relate — that the docs are an ordered set under /docs, that a post has a date and an author, that the thing all of it describes is a piece of software you can install for nothing. Three shapes, and a page gets whichever fits: a docs page TechArticle, plus the BreadcrumbList that renders as Docs › Guides › Key Bindings in a result rather than a bare URL. `page.group` is the front matter the sidebar already groups on, so the trail costs nothing to keep true. a blog post BlogPosting, same fields, no trail — /blog is flat. the home page SoftwareApplication. Deliberately without an aggregateRating: there is no review data behind one, and inventing it is the kind of markup that earns a manual action. Written as one file with three conditions rather than three includes: what differs between them is a handful of lines, and a Liquid tag inside a comment is still parsed, so the conditions are named in prose here rather than quoted. {% endcomment %} {%- assign page_url = meta_url -%} {%- if page.categories contains "docs" -%} {%- assign schema_type = "TechArticle" -%} {%- elsif page.date -%} {%- assign schema_type = "BlogPosting" -%} {%- endif -%} {%- if schema_type %} {%- endif %} {%- if page.group %} {%- endif %} {%- if page.url == "/" %} {%- endif %}
