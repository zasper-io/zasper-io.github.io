Agents

Your agent works in your notebook. You keep the final say.

Claude Code, Gemini CLI, Codex or any agent that speaks ACP, in a panel beside the notebook it is working on. Zasper gives it the live kernel, and every change it makes is yours to review and undo.

  1. 01 · Bring

    Your agent, your account

    Signed in with your own subscription. Zasper holds no key and sends none of the conversation anywhere.

  2. 02 · Work

    Cells in the live kernel

    It reads cells and outputs, edits cells, runs them, and inspects variables and dataframes. Plots come back to it as images.

  3. 03 · Ask

    Nothing behind your back

    It asks before it edits a file or runs a command, unless you allow it. Each run shows in its cell, under the agent's name.

  4. 04 · Review

    Undo a block, a cell or a turn

    Every file a turn changed is listed with a diff. Put back one change, one file, or the whole turn.

Already run an agent in a terminal?

Zasper is an MCP server too. Register it once, and Claude Code, Codex, Cursor or Gemini CLI drives the notebooks you have open, each run landing in its cell as you watch.

claude mcp add zasper -- zasper mcp

Coding agents covers the panel, its permissions and undo; MCP server covers agents you run outside Zasper.

Open by design

Your notebooks stay yours. So does everything around them.

A hosted notebook keeps your work in its cloud, in its format, and on its bill. Zasper is a binary you run, on files you already have.

  • Your files

    Plain .ipynb, in your git

    Notebooks stay in your own folder, saved as Jupyter saves them. Nothing to import, and nothing lost on the way out.

  • Your agent

    On the plan you already pay for

    Claude Code, Gemini CLI, Codex or any ACP agent, on your own subscription. No AI credits to buy, and no key held.

  • Your machine

    Your laptop, or your server

    Code, data and outputs stay where you put them. Run it for a team on a box you control.

  • Your license

    Free and open source

    AGPL-3.0: install it, run it, change it. A commercial license is there for products that need one.

Benchmarks

The gap widens as the load does

Both servers were run against the same workload, 10 requests per second per kernel on an Apple M4, from 2 concurrent kernels up to 100. Zasper uses less of both at every load, and the RAM gap grows with concurrency, from about 4× at 2 kernels to 38× at 100. At 64 kernels Jupyter Server begins losing kernel connections, and by 100 it has lost all of them, while Zasper answers every request at both loads.

CPU is averaged across each run; RAM is the highest figure observed. The figures above round the widest gaps: 4.5× less CPU at 4 kernels and 38× less RAM at 100. At 2 kernels the difference is about 3× for CPU and 4× for RAM. The CPU gap does not grow with load, while the RAM gap does. The crosses are measured the same way as the lines, as replies received against requests sent, which is flat at five replies per request until a server stops answering. Jupyter's 14% CPU at 100 kernels is 14% while returning nothing. Every point is recomputed from the raw runs in zasper-benchmark, where the harness and the methodology are public.

Kernels

Every kernel you already run

Zasper launches kernels through Jupyter's own kernelspec mechanism, so a kernel that runs under Jupyter runs here without being registered again.

{% include kernel-row.html %}

Python covers two implementations, ipykernel and Xeus (xeus-python). Every registered kernel is listed, and so is any Python environment Zasper finds with ipykernel in it. The launcher above shows three Python kernels, one of them Xeus. Installing kernels walks through adding your own.

Deployment

Your laptop, or your server

The same binary either way. Run it on the machine in front of you, or put it on a box and open it from anywhere. A footprint this small is what makes a shared server cheap.

Signed in from the first run

Every server starts with an access token. Sign in with the link it prints, or paste the token; set it yourself to keep it across restarts.

Behind your own HTTPS

A reverse proxy in front, WebSockets passed through, and the certificate you already have.

Docker, or a service

A Dockerfile and a Compose file to build and run it in a container, and a systemd unit for when it should come back up with the machine.

Deploying on Cloud walks through all three, and both ways to sign in.

FAQ

Questions people actually ask

Is Zasper a drop-in replacement for JupyterLab?

For your notebooks and your kernels, yes: the same files, the same kernelspecs, the same wire protocol. For JupyterLab itself, no. This is a separate implementation with its own interface, not a re-creation of Lab's UI or its extension API.

How is Zasper different from a hosted notebook like Hex?

A hosted platform runs your code in its own cloud and keeps projects in its own format. Zasper runs on your machine or your server, your notebooks stay .ipynb files in your folder, and your agent runs on your own subscription. Hex does more for a team publishing dashboards to people who do not code; Zasper is for the people writing the notebooks. Zasper and Hex, side by side has the details.

Do my JupyterLab extensions work?

No. Zasper has its own extension model rather than Lab's, so a lab extension will not load. If an extension is the reason you are staying, that is a fair reason to stay.

Does it work on Windows?

Yes, and there is a Windows build. The one part that needs WSL is the built-in terminal, which is built on a Unix pseudo-terminal; running the server under WSL gives you that too and is the setup we recommend.

Is it really free?

Yes, under the AGPL-3.0: install it, run it, put it on your own server, change it. The commercial license is for building Zasper into a proprietary product, which the AGPL does not allow.

What happens to my conda and uv environments?

One registered as a Jupyter kernel appears in the launcher as it does in Jupyter, without being registered again. Without a kernelspec, Zasper still lists one with ipykernel in it if it is active when Zasper starts, is your base conda install, or is the project's .venv in a trusted folder.

Which coding agents work, and what do they cost?

Claude Code, Gemini CLI and Codex, and any other agent that speaks ACP; Claude Code is the one tested most. Each runs on your own account and subscription, so Zasper adds no cost and holds no key. Agents you run outside Zasper can use it through its MCP server.

Does my code leave my machine?

No. Zasper runs a server on your own machine and your files stay on it. A coding agent you start talks to its own provider, as it does in a terminal. It sends anonymous usage data, with no file names, paths, contents or IP address, and ZASPER_TELEMETRY=0 switches it off; PRIVACY.md is the complete list. It also asks zasper.io once a day whether there is a newer version, and loads widget libraries it does not bundle from jsDelivr unless Load widget libraries from the internet is off in Settings.
